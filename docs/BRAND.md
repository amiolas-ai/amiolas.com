## 1. 회사 개요


| 항목        | 내용                                |
| --------- | --------------------------------- |
| **회사명**   | Amiolas                           |
| **한글 표기** | 아미올라스                             |
| **업종**    | AI Studio — 자체 AI 제품군 + 엔터프라이즈 엔지니어링(클라이언트 의뢰 기반 맞춤형 IT 시스템 설계·구축·운영) |
| **설립 단계** | 창업 준비 / 초기                        |


### 1-1. 미션 (Mission)

> **의미의 연속성을 회복합니다.**
> *Restore the continuity of meaning.*

단절된 곳에 의미의 연속성을 복원하는 일에 집중합니다. 문서·코드·메신저에 흩어진 채 잊히는 회사 지식 — 의미가 끊어지는 모든 자리에서. 이것이 Amiolas가 푸는 단 하나의 문제이며, 모든 제품·사업·의사결정의 방향을 정하는 기준입니다.

### 1-2. 메타포 (Metaphor)

> **"의미와 영혼의 연속성 — 이종 언어의 통합은 이질적 영혼의 통합을 요구한다."**
> *— Emilidis의 형이상학적 통찰 (R. Scott Bakker, The Second Apocalypse)*

회사명 **Amiolas**는 위 통찰을 바탕으로 제작된 마법 투구의 이름에서 차용했습니다. 이종의 언어를 이해하기 위해 이질적 영혼의 통합이 필요하다는 비유는, 서로 다른 "언어"로 흩어진 사내 데이터(GitHub · Notion · Drive · 코드 · 메신저)의 의미를 **한곳에서 연결해 읽어내야** 하는 우리 일의 본질과 같습니다. 원작 소설의 상세 배경은 §1-3 작명 어원을 참조하세요.

### 1-3. 작명 어원

캐나다 작가 **R. Scott Bakker**의 판타지 소설 시리즈 **The Second Apocalypse (제2의 묵시록)** 에 등장하는 마법 투구 **"Amiolas"** 에서 착안. (시리즈: *The Prince of Nothing* 3부작 + *The Aspect-Emperor* 4부작)

#### 원작 소설의 핵심 설정


| 항목         | 내용                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------- |
| **본질**     | 얼굴 전체를 감싸는 마법 투구                                                                                  |
| **별칭**     | **Embalming-Skull** · **Cauldron** — 인간들 사이에서 두려움의 대상으로 알려진 이름들                                  |
| **제작자**    | **Emilidis "The Artisan"** — 마법 유물을 다루는 장인 학파의 창설자                                                |
| **장인의 통찰** | "의미와 영혼의 연속성" — 이종 언어의 통합이 곧 이질적 영혼의 통합을 요구한다는 형이상학적 통찰 (자세한 풀이는 §1-2 메타포)                       |

## 2. 비즈니스 모델

Amiolas는 **AI Studio**입니다. 자체 AI 제품 라인과 엔터프라이즈 엔지니어링 사업을 병행하며, AI 제품 라인의 첫 출발은 **Specify**입니다. 이후 AI를 활용한 후속 제품을 순차적으로 추가해 제품군을 확장합니다.

```
                ┌────────────────────────┐
                │       Amiolas          │
                │     (AI Studio)        │
                └───────────┬────────────┘
                            │
            ┌───────────────┼───────────────┐
            ▼                               ▼
    ┌───────────────┐         ┌───────────────────────┐
    │  AI 제품 라인  │         │ 엔터프라이즈 엔지니어링 │
    │  ① Specify    │         │   (수주 프로젝트)       │
    │  ② …(예정)     │        │                       │
    └───────────────┘         └───────────────────────┘
       장기 성장 동력              운영 자금(캐시플로)
```

- **AI 제품 라인** (장기 성장 동력)
  - 첫 제품: **Specify** — Ontology AI-Agent · Open Beta 운영 중
  - 두 번째 제품: **세무 AI 에이전트** — 개발 진행중 (제품 브랜드명은 공식 발표 전까지 비공개)
  - 이후 AI를 활용한 후속 제품을 순차적으로 추가 (도메인은 검토 단계)
- **엔터프라이즈 엔지니어링 (Enterprise Engineering)** (운영 자금·캐시플로)
  - 클라이언트 의뢰 기반 맞춤형 IT 시스템 설계·구축·운영
  - 납품 사례: **맘마**(mamma.im) — 육아 기록·AI 성장 분석 앱
  - 목적: 초기 자금 마련 및 운영 자금(캐시플로) 안정화
  - **운영 원칙**: AI 제품 라인과 자원·인력·의사결정 흐름을 분리해 독립적으로 운영

## 3. 첫 번째 AI 제품 — Specify

### 3-1. 한 줄 정의

> 흩어진 기업 데이터를 하나의 지식 그래프(그래프 기반 온톨로지)로 엮어 **기업용 AI 두뇌(Corporate AI Brain)** 로 전환하는 서비스.

### 3-2. 핵심 기능


| 기능                    | 설명                                        |
| --------------------- | ----------------------------------------- |
| **Multi-Source RAG**  | GitHub, Notion, Google Docs 등 다중 소스 통합 검색 |
| **Semantic Linking**  | 실시간 맥락 연결, 문서 간 의미적 관계 자동 매핑              |
| **Insight Dashboard** | Knowledge Graph 시각화                       |
| **성과 지표**             | 정보 탐색 시간 **40% 단축**                       |


### 3-3. 문제 정의 / 타겟

- **타겟**: 사내 문서·코드·노션·드라이브가 흩어져 있는 중·대형 기업
- **페인 포인트**: "데이터 사일로(silo)" — 프로젝트 맥락이 단절되고 과거의 시행착오가 반복됨

### 3-4. 차별점 (Value Proposition)

- **Palantir의 온톨로지 문서 엔진 아키텍처**를 기반으로 한 "지식 자산화"
- 단순 저장·검색을 넘어 AI의 자율 추론으로 **"인사이트 역제안"**

### 3-5. 현재 상태

- **Open Beta** 진행 중
- 초기 가입자 약 20명

### 3-6. 관련 링크

- 서비스: [https://specify.app](https://specify.app)
- 프로젝트 소개: [https://hyunjoong.kim/ko/projects/graphrag-ai-agent-specify](https://hyunjoong.kim/ko/projects/graphrag-ai-agent-specify)

## 4. 카피 보이스 — 쉬운 한국어 원칙

기본 보이스 규칙(합쇼체 · no emoji · no exclamation · 3인칭 진술 · 구체 수치)은 상위 규칙으로 유지하고, 그 아래 세부 원칙으로 다음 5가지를 적용합니다. 모든 외부 노출 카피(웹사이트·메타데이터·IR)에 해당합니다.

| # | 원칙 | 설명 |
| --- | --- | --- |
| 1 | **첫 문장은 사실, 다음 문장은 의미** | 각 섹션 첫 문장은 "무엇을 하는 회사/제품인지"를 일상어로 진술합니다. 메타포 표현("의미를 잇는다")은 두 번째 문장 이후 보조로만 사용하며, 메타포 단독 노출은 금지합니다. 예외: 미션 슬로건("의미의 연속성을 회복합니다")은 OG 타이틀 등 슬로건 자리에서 단독 노출을 허용합니다. |
| 2 | **한 문장 한 정보** | 쉼표 나열로 정보 3개 이상을 욱여넣지 않습니다. 명사구 폭격 대신 끊어 씁니다. |
| 3 | **전문 용어는 첫 등장 시 풀어쓰기** | 본문에서는 일상어로 대체하거나 한 줄 풀이를 동반합니다. 영문 기술 용어(Multi-Source RAG 등)는 mono 메타 라벨로만 사용합니다. |
| 4 | **번역투·압축 한자어 금지 목록** | "통합 해독 → 한곳에서 연결해 읽어냄" · "역제안 → 먼저 제안" · "순차 확장 → 하나씩 늘려감" · "복원 → 다시 이음" · "캐시플로 → 운영 자금" · "한 통의 메시지로 → 메시지 한 통으로" |
| 5 | **영문은 장식·고유명사, 한글은 정보** | 읽고 이해해야 하는 텍스트(헤드라인·본문·CTA)는 한글로 씁니다. 분위기용 mono 라벨(eyebrow·aside·figcaption·stat)과 고유명사(Specify · Open Beta · AI Studio)는 영문을 유지합니다. |
